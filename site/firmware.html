Le firmware : ce qui tourne dans la carte

Un programme Arduino d'environ 470 lignes. Il initialise l'écran, écoute l'USB et le bouton BOOT, garde l'heure entre deux messages et redessine tout l'écran d'un bloc, sans scintillement.

00Vue d'ensemble

Tout programme Arduino a deux fonctions : setup(), exécutée une fois au démarrage, et loop(), rappelée en boucle ensuite. Ici, la boucle tourne environ 100 fois par seconde et fait deux choses : lire ce qui arrive sur l'USB, et redessiner l'écran toutes les 5 secondes.

Pourquoi Arduino et pas ESP-IDF ?

ESP-IDF, le framework officiel d'Espressif, est plus puissant, mais bien plus lourd à installer et à prendre en main. Pour un afficheur, Arduino suffit largement. Les démos LVGL de Waveshare restent disponibles si l'on veut plus tard une interface plus riche.

02Allumer l'écran

L'écran est relié en SPI, un bus série rapide à 4 fils. La bibliothèque a besoin de connaître les broches utilisées :

claude_usage.ino · broches et initialisation
#define PIN_MOSI 6     // données vers l'écran
#define PIN_SCLK 7     // horloge SPI
#define PIN_MISO 5     // données depuis la carte TF (inutile pour l'écran)
#define PIN_LCD_CS 14  // « c'est à toi » : sélection de l'écran
#define PIN_LCD_DC 15  // commande (0) ou donnée (1)
#define PIN_LCD_RST 21 // reset matériel de l'écran
#define PIN_LCD_BL 22  // rétroéclairage

Adafruit_ST7789 tft(&SPI, PIN_LCD_CS, PIN_LCD_DC, PIN_LCD_RST);

void setup() {
  pinMode(PIN_LCD_BL, OUTPUT);
  digitalWrite(PIN_LCD_BL, HIGH);          // sans lumière, on ne voit rien

  SPI.begin(PIN_SCLK, PIN_MISO, PIN_MOSI);
  tft.init(172, 320);                      // décalage de 34 px calculé par la lib
  tft.setSPISpeed(40000000);               // 40 MHz
  tft.setRotation(1);                      // paysage : 320 x 172
}

Le décalage de 34 pixels

Le contrôleur ST7789 est conçu pour des dalles de 240 × 320. Celle-ci ne fait que 172 pixels de large, centrée dans la mémoire du contrôleur. Il faut donc décaler chaque dessin de (240 − 172) / 2 = 34 pixels. Sinon, l'image est coupée d'un côté et des pixels parasites apparaissent de l'autre.

03Dessiner sans scintiller

Si l'on efface l'écran puis que l'on redessine élément par élément, l'œil voit l'écran clignoter au noir à chaque mise à jour. La solution classique est le rendu hors écran (double buffering) : on dessine dans une image en mémoire, puis on envoie cette image entière d'un coup.

claude_usage.ino · canvas
GFXcanvas16 canvas(W, H);  // image 320 x 172 en mémoire, 16 bits par pixel

static void render() {
  canvas.fillScreen(COL_BG);
  // ... tout le dessin se fait dans canvas ...
  tft.drawRGBBitmap(0, 0, canvas.getBuffer(), W, H);  // envoi d'un bloc
}
CalculValeur
Taille de l'image : 320 × 172 pixels × 2 octets (couleur RGB565)110 080 octets (≈ 108 Ko)
Mémoire vive de l'ESP32-C6 (sans PSRAM)512 Ko, dont ≈ 310 Ko libres pour le programme
Temps d'envoi à 40 MHz : 110 080 × 8 bits / 40 000 000≈ 22 ms, invisible à l'œil
RGB565, c'est quoi ?

Chaque pixel tient sur 16 bits : 5 pour le rouge, 6 pour le vert (l'œil y est plus sensible), 5 pour le bleu. Le firmware convertit les couleurs habituelles avec c565(r, g, b). Par exemple, l'orange de Claude #D97757 devient c565(217, 119, 87).

L'écran fait 320 × 172 pixels en paysage. Chaque zone a une position fixe :

Les polices viennent d'Adafruit GFX : FreeSansBold12pt7b pour les pourcentages, FreeSans9pt7b pour le texte. Le suffixe 7b signifie « 7 bits », c'est-à-dire l'ASCII seul, sans accents. C'est pour cette raison que le pont retire les accents des messages.

05Recevoir une trame

Les octets arrivent un par un sur l'USB. pollSerial() les accumule dans un tampon jusqu'au retour à la ligne, puis confie la ligne complète à handleLine() :

claude_usage.ino · pollSerial
static void pollSerial() {
  static char line[200];
  static size_t len = 0;
  while (Serial.available()) {
    char c = Serial.read();
    if (c == '\n' || c == '\r') {
      if (len) {
        line[len] = 0;
        handleLine(line);
        len = 0;
        render();      // redessin immédiat : la nouvelle valeur s'affiche sans attendre
        updateLed();
      }
    } else if (len < sizeof(line) - 1) {
      line[len++] = c;  // au-delà de 199 caractères, le surplus est ignoré
    }
  }
}

Pour découper la ligne, la fonction classique strtok ne convient pas : elle fusionne les séparateurs consécutifs, si bien que le champ « erreur » vide décalerait tout. Le firmware fait donc son propre découpage, qui conserve les champs vides :

claude_usage.ino · handleLine
static void handleLine(char *line) {
  if (line[0] == '?') {                       // identification
    Serial.println("MINIDISPLAY claude_usage 1");
    return;
  }
  if (line[0] != 'Q' || line[1] != ';') return;

  char *f[9];
  int n = 0;
  char *p = line;
  while (n < 9) {                            // découpage qui conserve les champs vides
    f[n++] = p;
    char *sep = strchr(p, ';');
    if (!sep) break;
    *sep = 0;                                 // remplace ';' par une fin de chaîne
    p = sep + 1;
  }
  if (n < 8) return;                         // trame incomplète : ignorée

  st.pcNow = strtoul(f[1], NULL, 10);
  st.rxMs = millis();                         // instant de réception, pour l'horloge
  st.five.used = atoi(f[2]);
  st.five.reset = strtoul(f[3], NULL, 10);
  st.week.used = atoi(f[4]);
  st.week.reset = strtoul(f[5], NULL, 10);
  st.level = atoi(f[6]);
  st.updated = strtoul(f[7], NULL, 10);
  snprintf(st.err, sizeof(st.err), "%s", n > 8 ? f[8] : "");
  st.have = true;
  Serial.println("OK");
}
Le découpage se fait sur place : chaque ; est remplacé par un octet nul, et f[i] pointe sur le début de chaque champ. Aucune copie, aucune allocation.

06Une horloge sans horloge

La carte n'a pas d'horloge temps réel, et pas d'Internet pour se mettre à l'heure. Elle dispose seulement de millis() : le nombre de millisecondes écoulées depuis son démarrage. Cela suffit, à condition de mémoriser à quel moment est arrivée la dernière heure connue :

claude_usage.ino · nowLocal
static uint32_t nowLocal() {
  return st.pcNow + (millis() - st.rxMs) / 1000;
}

Exemple : la trame annonce 10:43:09, reçue quand millis() valait 600 000. Douze secondes plus tard, millis() vaut 612 000 et nowLocal() renvoie 10:43:21. Toutes les 30 secondes, une nouvelle trame remet les pendules à l'heure : la dérive du quartz n'a pas le temps de s'accumuler.

Pour transformer ce nombre en « 21:00 » ou « jeudi 18:00 », le firmware utilise gmtime_r(), la fonction standard qui convertit des secondes en date. Le pont a déjà fourni des secondes « en heure locale » (voir le piège des heures), donc aucun fuseau n'intervient ici.

07Le calcul des jauges

Le repère de temps

Le trait blanc indique quelle part de la fenêtre est déjà écoulée. La fenêtre a commencé durée heures avant la remise à zéro :

claude_usage.ino · windowFraction
// Part écoulée de la fenêtre (0..1), ou -1 si l'heure de reset est inconnue.
static float windowFraction(const Gauge &g, uint32_t hours) {
  if (!g.reset || !st.have) return -1;
  const float span = hours * 3600.0f;
  float f = ((float)nowLocal() - ((float)g.reset - span)) / span;
  return f < 0 ? 0 : (f > 1 ? 1 : f);
}

La couleur

La couleur ne dépend pas de la consommation brute, mais de l'écart signé entre la consommation et le repère. Elle reste dans la palette de Claude et change par nuances, sans paliers brusques :

claude_usage.ino · gaugeRGB
const RGB RGB_TERRA = { 217, 119, 87 };   // dans le rythme : terracotta Claude
const RGB RGB_RED = { 229, 72, 77 };      // en avance sur le rythme : risque de manquer
const RGB RGB_CLOUD = { 177, 173, 161 };  // en retard sur le rythme : de la marge

static RGB gaugeRGB(const Gauge &g, float frac) {
  if (g.used < 0) return RGB_UNKNOWN;        // valeur inconnue
  if (frac < 0) return RGB_TERRA;            // reset inconnu : pas de repère
  const float gap = g.used - 100.0f * frac;  // > 0 : on consomme plus vite que le temps
  float t = (fabsf(gap) - 10.0f) / 25.0f;    // 0 jusqu'à 10 points, 1 à 35 points
  t = t < 0 ? 0 : (t > 1 ? 1 : t);
  return lerpRGB(RGB_TERRA, gap > 0 ? RGB_RED : RGB_CLOUD, t);
}
lerpRGB mélange deux couleurs canal par canal : avec t = 0,5, on obtient la teinte à mi-chemin. La même nuance sert à l'écran et à la LED.
Écart avec le repèreCouleurLecture
Moins de 10 points■ terracottaDans le rythme
En avance de 10 à 35 points■→■ vers le rougeConsommation trop rapide : risque de manquer avant la remise à zéro
En retard de 10 à 35 points■→■ vers le gris chaudDe la marge : le quota ne sera pas épuisé
Au-delà de 35 pointsrouge ou gris chaud pleinÉcart franc
Exemple chiffré

Session de 5 h, remise à zéro à 14:50, il est 12:20. La fenêtre a commencé à 09:50, et 2 h 30 sur 5 h sont écoulées : le repère est à 50 %. La consommation est de 28 %, soit 22 points de retard sur le repère : t = (22 − 10) / 25 ≈ 0,5. La jauge est à mi-chemin entre terracotta et gris chaud : il reste de la marge.

Pourquoi avoir quitté le bleu, le vert et le rouge ?

La première version reprenait la règle du widget PC : l'écart comptait dans les deux sens, si bien qu'un quota largement inutilisé virait au rouge, comme un quota sur le point d'être épuisé. La nouvelle règle distingue le sens de l'écart : seul le rouge signale un vrai risque. Et sur un écran dédié et rétroéclairé, la palette de Claude rend l'ensemble plus cohérent.

Le trait blanc est dessiné par-dessus la barre, avec un liseré de la couleur du fond de part et d'autre (3 px), pour rester visible quelle que soit la couleur dessous.

08Les états dégradés

Le pied d'écran raconte toujours ce qui se passe. Les cas sont testés dans cet ordre :

ConditionPied d'écranJauges

Dernière trame il y a plus de 2 min« PC deconnecte depuis N min »Grisées, dernières valeurs
Le champ erreur n'est pas videLe message, en orangeNormales, ou « -- »
Tout va bien« Releve a 10:43 »Normales
claude_usage.ino · isStale
#define STALE_MS 120000UL  // au-delà, le PC est considéré déconnecté

static bool isStale() {
  return !st.have || millis() - st.rxMs > STALE_MS;
}
La soustraction millis() - st.rxMs reste juste même quand millis() repasse par zéro, au bout d'environ 49 jours, grâce à l'arithmétique des entiers non signés.

09La LED

La LED RGB sur GPIO8 éclaire la plaque d'acrylique. Elle reprend la nuance exacte de la jauge de session, avec une luminosité réduite à 25 sur 255 pour ne pas éblouir. Elle s'éteint quand il n'y a pas de données.

claude_usage.ino · updateLed
static void updateLed() {
  uint32_t c = 0;                                   // éteinte par défaut
  if (!isStale() && st.five.used >= 0) {
    const RGB k = gaugeRGB(st.five, windowFraction(st.five, 5));
    c = rgb.Color(k.r, k.g, k.b);                   // même nuance que la jauge
  }
  rgb.setPixelColor(0, c);
  rgb.show();
}

10Le bouton BOOT

L'écran n'est pas tactile. La carte a deux boutons : RESET redémarre la puce, et BOOT, relié à GPIO9, ne sert qu'au démarrage. Une fois le programme lancé, BOOT est donc un bouton libre. Aucune soudure n'est nécessaire.

GesteEffet
Appui court (moins de 0,7 s)Vue suivante : jauges → gros chiffres → horloge → crédits ElevenLabs → PC → Pomodoro → commandes repas → action → jauges…
Appui long (0,7 s)Thème suivant : Matrix, MS-DOS, Windows 98, Ubuntu, Claude Code (par défaut), macOS clair et Aperture Science. Un message le confirme en pied d'écran. (Le réglage de luminosité reste dans le code, désactivé par LONG_PRESS_BRIGHTNESS.)

Six points en bas à droite indiquent la vue affichée. Vue, thème et luminosité sont enregistrées en Flash : elles survivent à un débranchement.

claude_usage.ino · pollButton
// Appui court (relâché avant 700 ms) : vue suivante. Appui long : thème suivant,
// déclenché dès les 700 ms atteintes, sans attendre le relâchement.
static void pollButton() {
  static bool down = false, longDone = false;
  static uint32_t t0 = 0, lastChange = 0;
  const bool pressed = digitalRead(PIN_BOOT) == LOW;  // actif à l'état bas
  const uint32_t now = millis();

  if (pressed != down && now - lastChange > 30) {     // anti-rebond
    lastChange = now;
    down = pressed;
    if (down) {
      t0 = now;
      longDone = false;
    } else if (!longDone) {
      nextView();
    }
  }
  if (down && !longDone && now - t0 >= LONG_PRESS_MS) {
    longDone = true;
    if (LONG_PRESS_BRIGHTNESS) nextBrightness();
    else nextTheme();
  }
}
Anti-rebond : un contact mécanique « rebondit » pendant quelques millisecondes et produit plusieurs fronts. On ignore donc tout changement survenu moins de 30 ms après le précédent.

Mémoriser les réglages

La bibliothèque Preferences écrit de petites valeurs dans une zone de la Flash prévue pour cela (la NVS), sous forme de paires clé-valeur :

claude_usage.ino · setup
prefs.begin("mdma", false);                          // espace de noms « mdma »
view = prefs.getUChar("view", VIEW_GAUGES) % VIEW_COUNT;
blIndex = prefs.getUChar("bl", 0) % 3;

ledcAttach(PIN_LCD_BL, 5000, 8);                     // rétroéclairage en PWM 5 kHz, 8 bits
ledcWrite(PIN_LCD_BL, BL_LEVELS[blIndex]);           // 255, 110 ou 35
La luminosité passe par la PWM : le rétroéclairage est allumé et éteint 5000 fois par seconde, et la proportion du temps allumé fixe la luminosité perçue. Le % VIEW_COUNT protège contre une valeur corrompue en Flash.
Ne pas maintenir BOOT en branchant la carte

Maintenu au moment du démarrage, BOOT fait entrer la puce en mode téléchargement : l'écran reste noir. Il suffit de rebrancher la carte, ou d'appuyer sur RESET.

11Pièges rencontrés

« 'Gauge' does not name a type »

Première compilation, première erreur. Avant de compiler un .ino, l'outil Arduino génère automatiquement les déclarations de toutes les fonctions et les place en haut du fichier, donc avant la définition des types qu'elles utilisent. Une fonction qui prend un Gauge devient alors illisible pour le compilateur.

Solution : déplacer les types dans un en-tête state.h, inclus en haut du fichier. L'en-tête est lu avant les déclarations générées.

firmware/claude_usage/state.h
// Types partagés : dans un en-tête pour que les prototypes générés par Arduino les voient.
#pragma once
#include <stdint.h>

struct Gauge {
  int used;        // %, -1 = inconnu
  uint32_t reset;  // heure locale du reset, 0 = inconnue
};

struct State {
  bool have = false;
  uint32_t pcNow = 0;  // horloge du PC au moment de la réception
  uint32_t rxMs = 0;   // millis() à la réception
  Gauge five = { -1, 0 };
  Gauge week = { -1, 0 };
  int level = -1;
  uint32_t updated = 0;  // heure du dernier relevé de quota réussi
  char err[72] = "";
};

« usage » par-dessus « Claude »

Sur la première photo, le mot « usage » chevauchait « Claude ». La largeur de « Claude » était mesurée après le passage à la petite police, donc trop courte. Les mesures de texte dépendent de la police active au moment de l'appel.

Avant / après
// Avant : textWidth() mesure avec FreeSans9pt, pas avec la police du titre
canvas.setFont(&FreeSans9pt7b);
drawLeft("usage", MX + textWidth("Claude") + 6, 22, COL_DIM);

// Après : on mesure tant que la police du titre est active
drawLeft("Claude", MX, 22, COL_CLAUDE);
const int16_t titleW = textWidth("Claude");
canvas.setFont(&FreeSans9pt7b);
drawLeft("usage", MX + titleW + 6, 22, COL_DIM);

12Compiler et téléverser

Git Bash, depuis la racine du projet
A="$LOCALAPPDATA/arduino-cli/arduino-cli.exe"
FQBN="esp32:esp32:esp32c6:CDCOnBoot=cdc"

powershell -ExecutionPolicy Bypass -File bridge/Stop-MiniDisplayBridge.ps1   # libère le port
"$A" compile --fqbn "$FQBN" firmware/claude_usage
"$A" upload  --fqbn "$FQBN" -p COM3 firmware/claude_usage
CDCOnBoot=cdc fait passer Serial par l'USB natif : c'est indispensable pour que la carte entende le pont. Le programme occupe environ 360 Ko, soit 27 % de l'espace disponible.
