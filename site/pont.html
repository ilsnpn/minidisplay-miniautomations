Le pont : la passerelle entre Claude et la carte

Un script PowerShell d'environ 300 lignes qui tourne en arrière-plan. Il récupère le quota, se protège des refus de l'API, trouve la carte sur l'USB et lui envoie une ligne de texte toutes les 30 secondes.

00Son rôle

Le pont est le seul programme qui parle à la fois à Internet et à la carte. Il fait le travail compliqué (authentification, erreurs réseau, fuseaux horaires) pour que le firmware n'ait plus qu'à afficher des nombres.

Ce qu'il faut retenir

Entrée : le jeton de Claude Code et deux URL. Sortie : une ligne de texte comme Q;1792233789;29;1792248600;29;1792692000;0;1792233787; envoyée sur le port COM de la carte.

Il reprend volontairement la méthode du widget ClaudeStatus : même endpoint, même jeton, mêmes garde-fous. Le widget a déjà prouvé que cette méthode fonctionne.

01La boucle principale

Le script est une boucle infinie qui se réveille toutes les demi-secondes et se pose trois questions :

bridge/MiniDisplayBridge.ps1 · boucle
while ($true) {
    $now = Get-Date
    $changed = $false
    if ($now -ge $NextStatus) { Update-Status; $changed = $true }
    if ($now -ge $NextQuota)  {
        Update-Quota; $changed = $true
        if ($Quota.Error) { Write-Log "Quota : $($Quota.Error)" }
        else { Write-Log ("Quota : 5 h {0} %, semaine {1} %" -f $Quota.Five, $Quota.Week) }
    }
    if ($changed -or $now -ge $NextSend) {
        $ok = Send-Frame
        $NextSend = $now.AddSeconds($(if ($ok) { $SendEverySeconds } else { 5 }))
        if ($Once) { break }
    }
    Start-Sleep -Milliseconds 500
}
Trois échéances indépendantes : $NextStatus, $NextQuota et $NextSend. Le paramètre -Once permet un test unique : un envoi, puis le script s'arrête.

02Étape 1 · Trouver le jeton

L'API de quota exige d'être authentifié. Le pont ne demande aucun mot de passe : il réutilise le jeton OAuth que Claude Code enregistre sur le PC quand on s'y connecte.

Get-OauthToken
function Get-OauthToken {
    if ($env:CLAUDE_CODE_OAUTH_TOKEN) { return ([string]$env:CLAUDE_CODE_OAUTH_TOKEN).Trim() }
    $f = Join-Path $env:USERPROFILE '.claude\.credentials.json'
    if (Test-Path $f) {
        try {
            $o = (Get-Content -Path $f -Raw -Encoding UTF8) | ConvertFrom-Json
            if ($o.claudeAiOauth -and $o.claudeAiOauth.accessToken) { return [string]$o.claudeAiOauth.accessToken }
        } catch { }
    }
    return $null
}
  • Ordre de recherche : d'abord la variable d'environnement CLAUDE_CODE_OAUTH_TOKEN si elle existe, sinon le fichier %USERPROFILE%\.claude\.credentials.json, champ claudeAiOauth.accessToken.
  • Relu à chaque appel : le jeton expire au bout d'une heure environ. Claude Code le renouvelle tout seul dans le fichier, et le pont profite donc toujours de la dernière version.
Limite à connaître

Si Claude Code n'a pas tourné depuis plus d'une heure, le jeton est périmé : l'API répond 401 et l'écran affiche « jeton expire, lancez Claude Code ». Il suffit de l'ouvrir un instant.

Sécurité

Le jeton ne sort du PC que vers api.anthropic.com, en HTTPS. Il n'est jamais écrit dans le journal ni envoyé à la carte.

03Étape 2 · Interroger l'API de quota

Une simple requête GET, avec trois en-têtes :

Update-Quota · la requête
$QuotaUrl = 'https://api.anthropic.com/api/oauth/usage'

# Le User-Agent compte : sans lui l'endpoint rate-limite beaucoup plus vite.
$r = Invoke-Get -Url $QuotaUrl -UA 'claude-code/1.0.0' -Headers @{
    'Authorization'  = 'Bearer ' + $tok
    'anthropic-beta' = 'oauth-2025-04-20'
}
En-têteValeurRôle
AuthorizationBearer <jeton>Prouve votre identité
anthropic-betaoauth-2025-04-20Active l'authentification OAuth sur l'API
User-Agentclaude-code/1.0.0Constat empirique : sans lui, les refus 429 arrivent beaucoup plus vite

La réponse est un JSON. Le pont n'en lit que deux blocs :

Réponse (extrait simplifié)
{
  "five_hour": { "utilization": 28.0, "resets_at": "2026-10-17T12:50:00+00:00" },
  "seven_day": { "utilization": 29.0, "resets_at": "2026-10-22T16:00:00+00:00" }
}
utilization est un pourcentage, arrondi à l'entier par le pont. resets_at est en UTC, ce qui pose un problème traité à l'étape 5.
Endpoint non documenté

/api/oauth/usage n'est pas une API publique officielle. C'est celle qu'utilise Claude Code pour afficher l'utilisation. Elle peut changer sans préavis : si un jour l'écran reste sur « quota indisponible », c'est la première piste à vérifier.

La requête elle-même passe par System.Net.HttpWebRequest plutôt que par Invoke-RestMethod. Ce choix permet de récupérer proprement le code HTTP en cas d'erreur, de forcer TLS 1.2 sur PowerShell 5.1 et d'utiliser le proxy système, ce qui est utile en entreprise.

04Étape 3 · Se protéger du rate-limit

L'endpoint refuse les appels trop fréquents avec un code 429 Too Many Requests. Le pont applique deux garde-fous :

  1. Jamais plus d'un appel toutes les 5 minutes, quoi qu'il arrive.
  2. Attente exponentielle après un refus : l'attente double à chaque 429 consécutif, jusqu'à 60 minutes au plus.
Refus consécutifs1234 et plus
Attente avant le prochain essai10 min20 min40 min60 min
Update-Quota · gestion des erreurs
if ($r.Code -eq 429) {
    if ($script:QuotaBackoff -lt $QuotaMinMinutes) { $script:QuotaBackoff = $QuotaMinMinutes }
    $script:QuotaBackoff = [math]::Min($QuotaMaxMinutes, $script:QuotaBackoff * 2)
    $script:NextQuota = $now.AddMinutes($script:QuotaBackoff)
    $script:Quota.Error = "trop d'appels, nouvel essai dans $($script:QuotaBackoff) min"
    return
}
if ($r.Code -eq 401 -or $r.Code -eq 403) {
    $script:Quota.Error = 'jeton expire, lancez Claude Code'
    $script:NextQuota = $now.AddMinutes(15)
    return
}

Pendant une attente après un 429, la carte garde les dernières valeurs connues : le quota n'a pas pu changer beaucoup. Après un 401, en revanche, les valeurs sont masquées, car elles peuvent être périmées depuis longtemps.

Widget et pont en même temps

Si le widget ClaudeStatus tourne aussi, chacun appelle l'API de son côté, soit deux appels toutes les 5 minutes. En cas de 429 à répétition, il faut couper le quota de l'un des deux.

06Étape 5 · Le piège des heures

L'API donne les heures de remise à zéro en UTC. Or la carte n'a ni fuseau horaire, ni règle d'heure d'été, ni connexion à un serveur de temps. Lui apprendre tout cela coûterait cher. L'astuce est de faire tout le travail sur le PC :

ConvertTo-LocalEpoch
$Epoch = New-Object DateTime 1970, 1, 1, 0, 0, 0, ([DateTimeKind]::Unspecified)

function ConvertTo-LocalEpoch {
    # Secondes depuis 1970 de l'heure locale "a plat" : la carte l'affiche telle quelle.
    param($Date)
    if (-not $Date) { return 0 }
    $d = [datetime]::SpecifyKind([datetime]$Date, [DateTimeKind]::Unspecified)
    return [int64][math]::Floor(($d - $Epoch).TotalSeconds)
}
Le passage à l'heure d'hiver est géré automatiquement, parce que Windows connaît les règles et que le pont reconvertit à chaque appel.

L'arrondi à la minute

Premier retour visuel : la semaine affichait « reset jeu. 17:59 » au lieu de 18:00. L'API renvoie en effet parfois 17:59:59.9, et la carte tronque les secondes. Le pont arrondit donc à la minute la plus proche :

ConvertTo-LocalTime
$d = ([datetime]::Parse($Iso, [System.Globalization.CultureInfo]::InvariantCulture, $styles)).ToLocalTime()
# L'API renvoie souvent 17:59:59.9 pour 18:00 : arrondi a la minute.
return $d.AddSeconds(30).AddTicks(-($d.AddSeconds(30).Ticks % [TimeSpan]::TicksPerMinute))
On ajoute 30 s, puis on coupe à la minute : 17:59:59.9 devient 18:00:29.9, puis 18:00:00.

Les accents

Les polices du firmware ne contiennent que les caractères ASCII. Un message comme « jeton expiré » afficherait des symboles parasites. Le pont décompose donc chaque lettre accentuée (é → e + ´), retire l'accent, et supprime au passage le ;, qui sert de séparateur dans la trame :

ConvertTo-Ascii
$n = $Text.Normalize([Text.NormalizationForm]::FormD)
foreach ($c in $n.ToCharArray()) {
    if ([Globalization.CharUnicodeInfo]::GetUnicodeCategory($c) -eq [Globalization.UnicodeCategory]::NonSpacingMark) { continue }
    if ([int]$c -lt 32 -or [int]$c -gt 126 -or $c -eq ';') { continue }
    [void]$sb.Append($c)
}

08Étape 7 · Trouver la carte et lui parler

La détection automatique

Le numéro de port COM change selon le PC et le port USB utilisé. Plutôt que de le coder en dur, le pont cherche le périphérique par son identifiant USB. Le VID 303A est celui d'Espressif, le fabricant de l'ESP32 :

Find-BoardPort
function Find-BoardPort {
    if ($Port) { return $Port }
    # USB Serial/JTAG natif de l'ESP32-C6 : VID 303A, PID 1001, interface 00.
    $dev = Get-CimInstance Win32_PnPEntity -Filter "PNPDeviceID LIKE 'USB\\VID_303A%'" -ErrorAction SilentlyContinue |
        Where-Object { $_.Name -match '\((COM\d+)\)' } | Select-Object -First 1
    if ($dev -and $dev.Name -match '\((COM\d+)\)') { return $Matches[1] }
    return $null
}
La carte expose deux interfaces USB : le port série (MI_00, celui qu'on veut) et l'unité de débogage JTAG (MI_02, sans port COM). Le filtre sur « (COMx) » garde la bonne.

Le piège DTR / RTS

Sur l'USB natif de l'ESP32, les signaux de contrôle DTR et RTS sont détournés pour redémarrer la puce. C'est ainsi que l'outil de téléversement la réinitialise tout seul. Si le pont les activait à l'ouverture du port, chaque reconnexion redémarrerait la carte.

Open-Board
$sp = New-Object System.IO.Ports.SerialPort $name, 115200
$sp.NewLine = "`n"
$sp.WriteTimeout = 2000
# DTR/RTS restent bas : sur l'USB Serial/JTAG, les basculer reinitialise la puce.
$sp.DtrEnable = $false
$sp.RtsEnable = $false
$sp.Open()
Le débit de 115200 bauds est symbolique : sur un port USB natif (CDC), les données circulent à la vitesse de l'USB, quel que soit ce réglage.

Débranchement et rebranchement

Si l'écriture échoue (carte débranchée, redémarrée, port pris par le téléversement), le pont ferme le port et réessaie 5 secondes plus tard en relançant la détection. Il retrouve donc la carte tout seul, même si elle a changé de numéro de port.

Avant chaque téléversement

Un port COM ne peut être ouvert que par un seul programme à la fois. Tant que le pont tourne, l'outil de téléversement ne peut pas joindre la carte. Il faut d'abord l'arrêter :

Arrêter le pont
powershell -ExecutionPolicy Bypass -File bridge\Stop-MiniDisplayBridge.ps1
-ExecutionPolicy Bypass est nécessaire sur un Windows qui bloque les scripts par défaut. Le lanceur VBS l'utilise déjà.

10Option · Les crédits ElevenLabs

Le pont peut aussi afficher votre solde ElevenLabs sur une 4e vue de l'écran (appui court sur BOOT pour y accéder). C'est optionnel : sans clé, le pont fonctionne comme avant.

  1. Sur elevenlabs.io → Developers → API Keys, créez une clé. Dans les permissions, réglez Utilisateur sur Accès. Sans ce droit (user_read), l'API répond « missing the permission user_read ». Tout le reste peut rester sur « Pas d'accès ».
  2. Copiez bridge/secrets.env.example en bridge/secrets.env et collez-y la clé. Ce fichier est dans le .gitignore : la clé ne quitte jamais votre PC.
  3. Relancez le pont.
bridge/secrets.env
ELEVENLABS_API_KEY=sk_votre_cle_ici

Toutes les 10 minutes, le pont appelle GET https://api.elevenlabs.io/v1/user/subscription avec l'en-tête xi-api-key. Il lit les crédits consommés (character_count), la limite (character_limit) et la date de remise à zéro (next_character_count_reset_unix), puis envoie une seconde trame après la trame Q :

trame E
E;<utilises>;<limite>;<reset>;<updated>;<erreur>
E;17582;37472;1793849076;1792257096;
